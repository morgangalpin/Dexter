# 009.3 — Render Program

This document owns the behaviour of the single program that renders and verifies the printed-part
meshes under `Hardware/Models/`, the schema of the per-group `render.json` config it reads, and the
rules by which it runs work in parallel. It replaces the per-group `render-all.rs` scripts, the
`700-Differential/render-meshes.rs` script, `100-Base/check.rs` and `700-Differential/parts.json`.

## Goals

- One program serves every mesh group. A new group adds a `render.json` and no code.
- Group-specific data (part lists, reference meshes, tolerances, probe points, counts) lives in the
  group directory, never in the program.
- Independent OpenSCAD renders run concurrently, because a single OpenSCAD process uses one core.

## Command line

```
render.rs <group-dir | all> [--meshes] [--verify] [--config previous|revised]
                            [--jobs N] [--only ID] [--fail-fast]
```

| Option | Behaviour |
|---|---|
| `<group-dir>` | Run one group. `all` discovers every `*/render.json` under `Hardware/Models/` and merges the job graphs. |
| `--meshes` | Build the binary STL cache: render, settle, repair, pinch, and guard the volume. |
| `--verify` | Run the group's `checks`. With neither mode flag, `--verify` is implied. |
| `--config` | The configuration `--meshes` passes as `-D config=...`; default `revised`. A check names its own `config`, so one `--verify` run can hold both configurations. |
| `--jobs N` | Concurrent job limit; default is the number of available cores. |
| `--only ID` | Run the job and the jobs it depends on. |
| `--fail-fast` | Stop scheduling new jobs after the first failure. |

The exit status is 0 when every check passes and 1 otherwise.

## Config: `<group>/render.json`

```
{
  "ref_dir": <path relative to the group directory>,
  "parts":  [ { "id", "scad", "configs"?, "meshes"? } ],
  "checks": [ { "kind", "id", "after"?, "weight"?, ...fields of the kind } ]
}
```

- `parts` lists the printed parts in render order. An entry without `configs` is in every
  configuration; otherwise it is in the named configurations only. `meshes` (default true) controls
  inclusion in `--meshes`.
- `checks` lists the verification jobs. `id` is unique within the group and is referenced as
  `<group>/<id>` from other groups.
- `after` names the jobs that must finish first. A job runs when all of its `after` jobs have passed.
- `out` names the file a rendering check writes, and counts as a declared write without being listed in `writes`.
- `weight` (default 1) is the number of worker slots the job occupies, so memory-heavy renders can
  limit concurrency.
- `note` is accepted on any entry and any probe, carries the rationale, and is never interpreted.

### Check kinds

| Kind | Meaning |
|---|---|
| `render` | Render a source to a file and hold the render to silence. A `.csg` output evaluates every parameter and assertion without meshing. |
| `dist_gate` | Compare a rendered part with its reference mesh within a tolerance. |
| `clone` | `scadmesh compare` against a reference with per-part deviations and ignore ranges. |
| `seat` | Probe that a recess opens in the stated direction. |
| `fits` | Probe clearance and press fits at stated points. |
| `probes` | Material or void probes at stated points. |
| `counts` | `scadmesh teeth` counts at stated bands and slices. |
| `diameters` | `scadmesh slice` diameters. |
| `extents` | Bounding extents compared with a named OpenSCAD constant. |
| `interference` | Pairwise clash checks on an assembly. |
| `keepout` | Keep-out volume intersection. |
| `plate` | Plate bounding box and hole pattern read from a reference mesh. |
| `assembly_echo` | Render an assembly and read named `echo` values, which later jobs may use. |

The fields of each kind are defined by the unit tests of its module in `render-check/src/kinds/`.

## Scheduling rules

```mermaid
flowchart LR
    plan[Config + parts] --> graph[Job graph]
    graph --> ready{Dependencies passed?}
    ready -- yes --> worker[Worker pool, N slots]
    ready -- no --> graph
    worker --> report[Results printed in plan order]
```

- A job is a node; `after` entries are edges. A cycle or an unknown `after` target is a configuration
  error reported before any job runs.
- Two jobs must not declare the same output path. Every job declares its outputs, and duplicates are
  a configuration error.
- A job whose dependency failed is reported as skipped and counts as a failure.
- Each job's output is buffered and printed in plan order, so concurrent logs do not interleave.
- Worker slots are limited to `--jobs`; a job of weight `w` holds `w` slots.

## Migration

The migration proceeds group by group. Each ported group's verdicts are compared with the old
script's before the old script is deleted. The old scripts are removed only when every group is
ported.

| Mode | Group | Status |
|---|---|---|
| `--meshes` | 700-Differential | Ported and compared. All ten parts match the serial `render-meshes.rs` build in triangle count, with volume and area within 1e-11 relative. `render.json` replaces `parts.json`; `render-meshes.rs` stays until every group is ported. |
| `--verify` | 700-Differential | Kinds `render`, `dist_gate`, `clone`, `counts`, `diameters`, `fits`, `extents`, `interference` and `keepout` are ported and listed in its `render.json`. |
| `--verify` | other groups | Not ported. A check of an unported kind fails as "not yet ported". |

### Comparing mesh output

Byte equality between two renders is not a valid test. OpenSCAD writes a part's facets in a different
order from one process to the next, so two runs of the same program differ in bytes. `settle`'s vertex
snapping depends on that order, so a part that had vertices to settle may differ in the last float32
digit as well. Two mesh builds are equal when each part has the same triangle count and its volume
and area agree to about 1e-9 relative, and exactly equal as a set of triangles where nothing was settled.
